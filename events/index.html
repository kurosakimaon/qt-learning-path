⚡ 第叁阶段 · 事件系统

Qt 程序的心脏怎么跳 · 7 讲，从「事件循环」到「拖放」，全程不用鼠标键盘也能看见事件流

📖 模块简介

本模块讲 Qt 的事件系统（Event System）：事件循环（QCoreApplication::exec() / QEventLoop）、事件的三层派发（notify → event() → 具体 handler）、 事件过滤器（installEventFilter）、定时器（QTimer / timerEvent）、 鼠标键盘与焦点、自定义事件（QEvent::registerEventType）、拖放（QMimeData / QDrag）。 第 1 讲是总纲，第 2、3 讲是同一条派发链的两个视角（继承改行为 vs 不继承改行为）， 第 4~7 讲把四类具体的事件——定时器、输入、自定义、拖放——各钉死一讲。

本模块有一个核心技巧：所有示例都在没有鼠标、没有键盘的情况下把事件流演示出来—— 代码手工构造 QEvent / QMouseEvent / QKeyEvent / QDropEvent， 再用 QCoreApplication::sendEvent() / postEvent() 投给控件，然后打印计数与到达顺序当证据。 「点一下才知道收没收到」这种示例，本模块一个都不写。

环境事实：本资料库基于 Qt 6.12.0，Windows 平台，MinGW-w64 GCC 13.1.0（Qt 官方安装器自带：D:\Qt\Tools\mingw1310_64）， 构建用 CMake ≥ 3.21（本机 3.30.5）+ 生成器 MinGW Makefiles，语言标准 C++17（这是 Qt6 的最低要求）。 每讲都是完整可编译的示例 + 详细注释，且都设计成无人值守能自动跑完 （QTimer::singleShot 排脚本 + qInfo() 吐结论 + quit()）。

实测口径：本模块 7 个目标已在本机真实编译、链接、运行（Qt 6.12.0 + MinGW 13.1.0， Windows，QT_QPA_PLATFORM=offscreen），ctest -R events 7/7 全绿； 第 5、7 讲结尾各带一张自检台账（[PASS]/[FAIL]/[SKIP] 计数，本机那一轮 分别是 17 PASS / 0 FAIL / 0 SKIP 与 26 PASS / 0 FAIL / 0 SKIP），任何一条 FAIL 都会把退出码变成非 0， 所以「打印出来的结论」是被 ctest 盯着的。每个 .cpp 也过 moc + g++ -std=c++17 -Wall -Wextra（零 error、零 warning），文中每一个类、函数、枚举、重载 都对着本机真实头文件与源码逐字核对过（D:\Qt\6.12.0\mingw_64\include、 D:\Qt\6.12.0\Src\qtbase\src），注释里给到文件名与行号，perl _tools/audit_citations.pl 会把每条「第 N 行」再核一遍。完整输出存档在 runlogs/events_0N_*.log （UTF-8；重跑：bash _tools/run_all.sh '^events'）。 换 Qt 版本 / 换平台之后，带具体数字的预期以你自己那次打印为准；本机测不到的 （真实鼠标拖起的系统光标形状、跨进程 drop、Windows 上 QDrag::exec() 阻塞期间的界面表现） 在文中明确标成「文档语义」。

7 张卡片 = 7 讲，按 第 1 步 → 第 7 步 一张张往下学，别跳。 这个顺序的逻辑是：第 1 讲是总纲——事件循环不读懂，后面全是背； 第 2、3 讲是同一条派发链的两个视角——同一个事件从 notify() 落到你手上， 第 2 讲教你「继承 event()／handler 来改行为」，第 3 讲教你 「不继承、用事件过滤器从外面插手」，两讲合起来才是完整的拦截手段图谱，分开看都会以为只有一招； 第 4~7 讲是四类具体的事件——定时器（事件循环自己造的事件源，回验第 1 讲）、 输入与焦点（Qt5→Qt6 改动最集中的一片）、自定义事件（QEvent 子类 + postEvent 的真实语义）、 拖放（唯一要跨进程说话的一类）。
⚠️ 本模块有一道硬坎，就在 第 2 讲：「事件（event）与信号（signal）到底什么关系」 ——它太容易和上一模块（元对象系统）混在一起。务必记住这一句： 事件是系统层语义，信号是应用层语义。 事件（QEvent）来自窗口系统/QPA、由 notify() 派发、讲「谁发生了什么」，你重写 mousePressEvent() 接的是它；信号（Q_SIGNALS）是 Qt 自己造的应用层通知、 靠 moc 与 connect() 生效、讲「谁想让谁干什么」。两者交汇点在第 3 讲： 控件内部先在事件里翻译成信号（按下是 QMouseEvent，clicked() 是它的应用层结果）， 所以过滤器能吞掉 clicked()，但 btn->click() 直接发信号、绕过事件——这一条是检验你是否真分清的试纸。 每章重点与练习见 📖 学习指南。

01 · 事件循环解剖
把 app.exec() 这一行代码拆开：取事件 → 派发 → 再取；QEventLoop 可以嵌套，于是有了重入（re-entrancy）；processEvents() 何时是救急、何时是往火里浇油；quit() / exit(int) / 从槽里 return 的三种后果；sendEvent（同步）与 postEvent（入队）用实际到达顺序当证据。

第 2 步 · 事件 vs 信号
🧭
02 · 一次事件的三层传递
层 1 QApplication::notify（全程序唯一总入口）、层 2 receiver->event() 闸门、层 3 mousePressEvent / paintEvent 等具体 handler，逐层打印进入顺序。再看两件新手最容易翻车的事：重写 event() 拦一类事件；不调基类实现 → handler 不再被叫到、事件不再往父控件抛。accept/ignore 的真实语义。

第 3 步
🕳️
03 · 事件过滤器
「不继承就改行为」的唯一正统手段：installEventFilter 挂在目标对象上、qApp->installEventFilter 挂全局；true = 我吃掉（目标的 event() 不再被调用）、false = 看完继续传；同一目标多过滤器的调用顺序，与「过滤器和被过滤对象谁先死」的坑。末尾用按钮证明：吞掉事件能拦住 clicked()，而 btn->click() 绕过事件。

第 4 步 · 回验第 1 讲
⏱️
04 · 定时器家族
定时器是唯一由事件循环自己造出来的事件源：没有 exec()（或 processEvents），一次都不会响。QTimer 的单次三写法与重复；setTimerType 三档（Precise / Coarse / VeryCoarse）用 QElapsedTimer 实测间隔；低级路线 startTimer() + timerEvent(QTimerEvent*)，还能手工 sendEvent 一个 QTimerEvent 看穿它；interval=0 的合并行为。
进阶
第 5 步 · Qt5/Qt6 差异最集中
🖱️
05 · 输入事件与焦点
坐标体系 Qt6 全换成 QPointF：position() / scenePosition() / globalPosition()（Qt5 的 pos()/globalPos() 必考差异）；button()「谁变了」vs buttons()「此刻按住哪些」；双击的真实时序 Press→Release→DblClick；滚轮 angleDelta() 与 pixelDelta()、DefaultDeltasPerStep=120；键盘 key()/text()/modifiers()/isAutoRepeat()；Qt::FocusPolicy 五档与 tab 顺序；QShortcut + QKeySequence。
进阶
第 6 步
📮
06 · 自定义事件
别拍脑袋写 QEvent::User + 3：用 registerEventType() 动态注册（返回值每次运行都可能不同，所以不许硬编码整数值）；QEvent 子类怎么带数据、Qt6 新增的 clone() 为什么要重写；postEvent 的三条真实语义——所有权转移、优先级、同一接收者同一类型的合并；以及什么时候该改用信号：QueuedConnection 内部其实就是投一个 QMetaCallEvent。

第 7 步
🧲
07 · 拖放
事件系统里唯一要跨进程说话的一段：QMimeData 是唯一载体（setText/setUrls/setData + hasFormat/formats）；dragEnterEvent 里必须 acceptProposedAction()，只调 accept() 不够；dropEvent 怎么把数据接住（含自定义 MIME 的内部拖放特权）；真正拖动的启动阈值 manhattanLength() > QApplication::startDragDistance()，exec() 内部自开嵌套循环。示例用合成 QDragEnterEvent / QDropEvent 全程无鼠标演示。

📚 学习建议

  • 先跑第 1 讲再谈别的：事件循环是这 7 讲的地基。第 4 讲「没有 exec() 定时器一次都不响」、第 6 讲「postEvent 排到循环里才派发」、第 7 讲「QDrag::exec 自己开嵌套循环」，全是第 1 讲的复现。第 1 讲没跑通就往下走，后面只能靠背。
  • 把第 2、3 讲对照着看：同一条链，一个从里面改（重写 event()/handler），一个从外面插手（事件过滤器）。看完你要能回答：「我要改一个不是自己写的控件的行为，该用哪招？」——答案只能是过滤器。
  • 先答「事件还是信号」再动手：每写一段响应逻辑之前，先问自己接的是 QEvent 还是信号。分不清就把本模块 学习指南 第五节那张链图重看一遍。
  • 读打印出来的数字，别只读注释：每个示例都吐「到达顺序、进入次数、实测间隔」，本机那一轮已经存进 runlogs/events_0N_*.log（例：第 4 讲 interval=0 时 150ms 内命中 10803 次、重复 start() 2000 次的 B/A = 1.000）。绝对值随机器变，你要对上的是相对关系；跑不出同样的数不算你错，把那一行打印出来对比即可。
  • Qt5/Qt6 的差异标在注释里，迁移老代码时先看它：第 5 讲末尾有一张 Qt5→Qt6 对照表（pos()→position()、mouseButtons()→buttons()、QWheelEvent 构造参数变化、enterEvent 改收 QEnterEvent* 等），网上抄来的旧代码八成踩在这里。
  • 这 7 个目标本机都能跑：顶层 ctest -R events 就是它们的无人值守入口（强制 -platform offscreen，不需要显示器）；只想快速验证一份新机器上的源码，用 bash _tools/check_syntax.sh events（免链接）。自己改坏了也无妨——台账会把 FAIL 计数变成非 0 退出码，骗不过去。

👴 老师傅的话

徒弟，事件系统这块，是 Qt 里最「看得见」的一层，也是最容易被讲玄的一层。师傅不带你背 QEvent::Type 那几百个枚举，给你四条心法。

  • 第一条：一切都在循环里。 你的程序不是「从 main 走到 return」，而是「走进 exec() 就再不回来，直到有人叫停」。理解了这条，「show() 了没东西」「槽里跑大循环界面卡死」「定时器不响」这些症状，都是同一个病。
  • 第二条：事件是系统说的，信号是你自己说的。 别把两层混成一锅。窗口系统只会告诉你「按下在 (120,45)」，「用户点击了提交按钮」这句人话是控件把它翻译成信号之后的事。你要改行为，先想清楚要改的是哪一层的话。
  • 第三条：合成事件是你最好的实验台。 本模块最值钱的手法不是某个 API，而是「自己造一个事件投进去，看它怎么被层层接住」。从此调事件 bug 不用连鼠标、不用手点一百次，两行代码就能重现。这个习惯请带到以后所有 GUI 调试里去。
  • 第四条：不调基类实现，是「静默 bug」的温床。 重写 event() 忘了 return QWidget::event(e)，程序不会崩、不会报错，只是样式、焦点、父控件协作悄悄没了。第 2 讲用打印计数把这份「静默」放给你看，就是让你以后一眼认出它。

慢慢来。这 7 讲啃下来，你对 Qt 的理解就从「重写了一些虚函数」升级成「知道事件走到哪一层、被谁吃掉、还剩什么」。接下来的绘制、控件与布局、模型视图，全建在你现在能看见的这条派发链上。加油，徒弟！
