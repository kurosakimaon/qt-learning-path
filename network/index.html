🌐 第玖阶段 · 网络

get() 立刻返回，真正的工作在没有你的地方发生 · 5 章从 HTTP 到 TCP，全程只连回环

📖 模块简介

网络这一层最容易写歪，因为它天生异步，而新手总想把它拧成同步：在按钮槽里发个请求，然后「等它回来」。 你一「等」，事件循环就停了，界面就「未响应」，超时也没人管。Qt 网络的正确姿势只有一句话： 发出去、记住谁在等、回来再说。

本模块共 5 章：第 1 讲把 QNetworkAccessManager 的规矩立住（一个应用一个实例、六个动词、finished 之后才读结果）； 第 2 讲把网络层包成一层**可测试**的 API，并把失败分成三类（HTTP 语义错 / 网络错 / 解析错）； 第 3 讲自己写 TCP，直面「字节流里没有消息」这件事，用长度前缀造出边界； 第 4 讲做一个能扛事的下载任务（进度、Range 断点续传、边下边写、取消）； 第 5 讲 DNS 与 TLS——以及「这两个 API 都不给你超时，期限得自己加」。

关于联网的一条硬规矩：本模块涉及真实网络的示例只连本地回环（127.0.0.1 / QHostAddress::LocalHost），端口用 listen(QHostAddress::LocalHost, 0) 让内核挑，不访问公网。 需要外部服务的章节（DNS、TLS）写成了「能力探测 + 离线也成立的部分 + 你联网时的可选实验」，断网也能把课跑完。 所有等待都有期限，临时文件都在 QStandardPaths::TempLocation 下并且用完就删。

环境事实：Qt 6.12.0、Windows、MinGW-w64（MSYS2 ucrt64）、CMake ≥ 3.21 + Ninja、C++17。 目标名 network_01_network_access_manager … network_05_dns_and_ssl，已登记在顶层 CMakeLists.txt 的「第玖阶段 · 网络（network/）」一节，本组额外链 Qt6::Network。

诚实标注：本机当前无法编译链接 Qt 程序。本模块示例未链接、未运行；每个 .cpp 都过了 moc + g++ -fsyntax-only -std=c++17 -Wall -Wextra 的编译期核对（零 error、零 warning）。 每个类、函数、枚举值都对着本机 C:\msys64\ucrt64\include\qt6 里的真实头文件逐字核对过 （qnetworkrequest.h、qnetworkreply.h、qabstractsocket.h、qhostinfo.h……）。 真实网络的行为依赖对方服务器，文中凡是「对方会怎么答」的说法都写成条件句，不冒充实测。

📂 学习文件列表

5 张卡片 = 5 章，按 第 1 步 → 第 5 步 依次学。 这条主线是「先会用别人的协议（HTTP）→ 再把它包成工程上能测的一层 → 再自己造协议（TCP）→ 再做成扛得住断线的任务 → 最后解决名字与加密」： 第 1 步NAM 的规矩 → 第 2 步把失败分类 → 第 3 步字节流与边界 → 第 4 步下载状态机 → 第 5 步DNS 与 TLS。 本模块有两道硬坎： ① 第 1 步「finished 之前读到的是空」坎——error()、errorString()、 HttpStatusCodeAttribute 都只在 finished 之后才完整；readyRead() 是「又来了一段正文」， 不是「结束了」。你把这两件事混了，就会写出「正文永远只有第一段」的代码； ② 第 3 步「TCP 不给你消息」坎——一次 readyRead 可能是半条、两条、或者一个半； 粘包与半包不是 bug，是字节流的本性。边界必须自己造，而且长度字段是对端说的，永远别信。 网络是最容易「在我这儿能用」的一段：延迟、丢包、断线、重定向、慢服务器，你的开发机一样都不会遇到。 每章重点与练习见 📖 学习指南。

01 · QNetworkAccessManager 的正确姿势
一个应用一个 NAM（它内部有连接池、代理、Cookie、缓存、HSTS，每次 new 等于每次重新握手）；QUrl 的三个坑（手写字符串不是 URL、本地文件用 fromLocalFile、query 用 QUrlQuery）；六个动词（Qt6 没有 delete，只有 deleteResource）；finished 与 readyRead 的分工；error()/attribute() 只在 finished 之后完整；重定向策略与 setTransferTimeout。

02 · 把网络层写成可测试的一层
业务代码不该看见 QNetworkReply。RestClient::get/postJson 收回调、统一返回 ApiResult；三类失败分开建模——成功 / HTTP 语义错（4xx 5xx，服务器活着并答了你）/ 网络错（连不上、超时、被取消）/ 解析错（200 但正文不是 JSON），三者的提示、重试、日志级别都不同；请求头里 Authorization 不在 KnownHeaders 中，Bearer 只能 setRawHeader。
工程分层可测试性
第 3 步 · 第二道坎
🔌
03 · TCP：在字节流上盖出协议
事件驱动：newConnection / connected / readyRead / disconnected / errorOccurred / stateChanged 全是信号；端口现拿（listen(LocalHost, 0) + serverPort），并注意 listen 的默认地址是 Any——「桌面软件被防火墙弹窗」一半是顺手 listen() 造成的；一次 readyRead ≠ 一条消息（半包 3 次 write、粘包 2 帧 1 次 write 并排打印）；用长度前缀把帧找回来；connectToHost 返回 void，连不上只能等 errorOccurred。

04 · 下载任务的状态机
downloadProgress 的三个分支：总量 > 0 正常算百分比、== -1 是长度未知（别去做除法）、== 0 是空文件；熟头与生头的两种读法（Content-Range / Accept-Ranges 只在生头里）；断点续传 = Range 头 + 206 状态码 + Content-Range 回显，两段拼起来与整段逐字节比对；边下边写绝不攒内存（readyRead → read → QSaveFile::write）；取消用 abort() 而不是 deleteLater()。

QHostInfo 的同步与异步两套（fromName 堵线程、lookupHost + lookupId 对结果）；「查不到」是常态不是异常，用保留域名 .invalid 演示，并且证明「我们的期限一定生效」；QHostAddress 的五个事实（isLoopback / isNull / IPv4 与 IPv6 / LocalHost 与 Any）；TLS 能力探测：supportsSsl、后端名、密码套件、系统根证书——「能不能上 TLS」只有一个判据。

📚 学习建议

  • 一个应用一个 NAM：把它当成和 QApplication 同级的长期对象（通常是主窗口的成员，或者一个全局服务）。它创建的每个 reply 都归它管，但你必须自己 deleteLater()。
  • 只在 finished 之后读结果：error()、errorString()、状态码、大部分响应头，都是在这条信号之后才完整。正文可以边收边读，结论不行。
  • 三类失败分开处理：HTTP 4xx/5xx 是「服务器答了你，但它不同意」；网络错误是「它根本没答」；解析错误是「它答了，但答的不是你以为的东西」。混成一个 bool，你的提示、重试、日志就全错。
  • 自己写 TCP 就先定帧格式：长度前缀最简单（4 字节大端长度 + 正文），也最容易验证。定完帧格式，再写收发代码。
  • 所有等待都带期限：setTransferTimeout()、waitForReadyRead(期限)、QTimer 看门狗，三者至少有一个。setTransferTimeout 是「静默超时」，不是总时长上限。
  • 只连回环做实验：自己在本机起一个 QTcpServer 当被测服务端，你能控制它发半包、发坏帧、故意慢，这比连公网服务器有用得多。

👴 老师傅的话

徒弟，网络这块，手艺的高低不在「会不会发请求」，而在出事的时候你的程序是什么样。用户的地铁里没信号、公司的代理要认证、服务器偶尔返回 502、下载到 99% 断线——这些才是你真正要处理的东西。所以这一阶段我不教你「怎么把请求发出去」，我教你怎么把失败分成能处理的样子。

  • 第一条：永远不要同步等网络。 waitForFinished() 在你自己的 GUI 线程里就是一次自杀——事件循环停了，进度条不动，用户以为死了。除非你在一个专门的线程里、且知道自己在干什么。
  • 第二条：reply 是要还的。 finished 之后必须 deleteLater()，或者设 parent 让它随父消失。不还的 reply 会一条条攒着，直到你把内存吃光。
  • 第三条：状态码和错误是两个考场。 error() == NoError 只说明「传输层面走完了」，HttpStatusCodeAttribute 才说明「服务器怎么想」。两个都要看，缺一个就会把 500 当成成功。
  • 第四条：字节流里没有消息。 TCP 保证顺序和可靠，不保证边界。你要么用现成协议（HTTP 帮你划好了），要么自己造边界——长度前缀，然后防御坏长度。
  • 第五条：TLS 不是「开了就安全」。 先探测 supportsSsl()（有些 Qt 构建根本没编 OpenSSL 后端），再谈证书校验。连不上别急着忽略错误——那正是中间人的入口。
