🎨 第伍阶段 · 绘图与自定义控件

从「拿笔往哪儿画」到「造一个能复用的控件」 · 8 讲，每讲都吐出可核查的像素数字

📖 模块简介

徒弟，前四个阶段你一直在用别人画好的界面。这一关开始自己画。 本模块是一条完整的进阶链：第 1~4 讲把 QPainter 的地基铺平——基础图元、坐标变换、 画笔与画刷与渐变、文字度量与基线；第 5 讲回答「画布本身从哪来」—— QImage / QPixmap / QBitmap 的分工、字节布局与隐式共享； 第 6 讲把这一身本事包成一个可复用的控件（尺寸协商 + 鼠标交互 + 重绘策略）； 第 7 讲进高级绘制——QPainterPath、填充规则、裁剪与合成； 第 8 讲站在框架层面回答一个现实问题：什么时候别自己画了，改用 QGraphicsScene / QGraphicsView。

环境事实：本资料库基于 Qt 6.12.0，Windows 平台，MinGW-w64 GCC 13.1.0（Qt 官方安装器自带：D:\Qt\Tools\mingw1310_64）， 构建用 CMake ≥ 3.21（本机 3.30.5）+ 生成器 MinGW Makefiles，语言标准 C++17。本组 8 个目标统一 target_link_libraries(... PRIVATE Qt6::Widgets Qt6::Svg)（Svg 是给第 8 讲之后的项目留的， 前几讲只用到 Widgets）。每讲都无人值守自动跑完： QTimer::singleShot 排动作 → 画进 QImage → save("painting_0N_xxx.png") → qInfo() 打印 dimensions / 非透明像素数 / 采样像素值 → QCoreApplication::quit()。 没有 QDialog::exec()、没有裸 QEventLoop::exec()、没有静态 MessageBox。 跑完到 build/bin 下看图，图在就在证据在。

实测口径：本模块 8 个目标已在本机真实编译、链接、运行（Qt 6.12.0 + MinGW 13.1.0， Windows，QT_QPA_PLATFORM=offscreen），包含在顶层 ctest 的 73/73 里； 每个 .cpp 也过 moc + g++ -std=c++17 -Wall -Wextra（零 error、零 warning）， API 行号对着 D:\Qt\6.12.0\mingw_64\include 逐个查过。 27 张 PNG 现在是真的落到了 build/bin 下、一张 0 字节都没有， 打印数字的原始输出存档在 runlogs/<目标名>.log （重跑：bash _tools/run_all.sh '^painting'）。 ★ 但要说清楚边界：offscreen 那批 PNG 是 QImage 上画出来再存盘的证据， 不等于你在显示器上看到的那一帧——DPR、字体 hinting、合成器都会改观感。 「像素对不对」这件事仍然要靠肉眼开一次窗口；数字对不对，按上面那些打印复核。

8 张卡片 = 8 讲，按 第 1 步 → 第 8 步 一张张往下学，别跳。 顺序是一条「先会画 → 再懂布 → 然后成控件 → 最后换框架」的主线： 第 1~4 步是 Painter 的地基（图元 / 变换 / 画笔 / 文字）——这四步解决「一笔一笔怎么落」； 第 5 步讲像素从哪来——画布（QImage 与 QPixmap）本身是什么、 字节怎么排、复制了会不会共享； 第 6 步把绘制包成控件——从「一段画图代码」升级成「别人能放进布局里用的类」， 这一步是本模块的交付形态； 第 7 步是高级绘制——路径、填充规则、裁剪、合成，做「非矩形」「挖孔」「水印」全靠它； 第 8 步回答什么时候改用场景框架——图元多了、要缩放平移命中选择时， QGraphicsView 那套三件套比自绘控件划算得多。 本模块有两道硬坎：第 2 步的变换顺序（translate/rotate/scale 不可交换， 顺序错了整个控件就歪，靠打印两种顺序的结果自己看清楚）和 第 6 步的重绘策略（update() 与 repaint()、脏区、 以及 Qt::WidgetAttribute 那几个开关，用 10000 次调用只重画几次的数据来钉死）。 另外 QWidget 上并没有 setUpdateInterval() 这个函数（它属于 QTimeLine， 本机在 QtCore/qtimeline.h 第 65 行），第 6 讲给了四条真能用的限流路线。 每讲重点与练习见 📖 学习指南。

第 1 步
✏️
01 · QPainter 的三条铁律与基础图元
对控件作画只允许在 paintEvent() 里、对 QImage 随时可画（两条链同时出图对照）；painter 必须比设备早析构；begin()/end() 与 RAII、isActive() 自检；点/线/矩形/圆角矩形/椭圆/圆弧/扇形弦/多边形八件套；逻辑坐标 vs 设备坐标，1x 与 2x 画布实测着墨像素差约 4 倍。

02 · 坐标变换三件套与它们的顺序
translate/rotate/scale 不可交换：用 QTransform::map() 把同一端点在 A→B 与 B→A 两种顺序下的最终坐标打出来；save()/restore() 是整套状态栈（变换+笔+刷+字+裁剪）；worldTransform()/setWorldTransform() 与 operator* 的组合方向判别；viewport/window 映射；「绕某点旋转」为何要 translate→rotate→translate 回去；y 轴向下让角度正负看着相反。

05 · QImage / QPixmap / QBitmap：像素从哪来

06 · 做一个能复用的自定义控件

📚 学习建议

  • 每讲都要「看图 + 看数」两遍：跑完先去 build/bin 打开 painting_0N_*.png 看画面，再回头读 qInfo() 打印的 dimensions / 非透明像素数 / 采样像素值。画面会骗人，像素数不会。
  • 前四讲是地基，别急着跳去做控件：第 6 讲的自定义控件会同时用到第 2 讲的变换顺序和第 4 讲的基线计算；第 7 讲的裁剪又依赖第 2 讲的坐标概念。跳着学，第 6 讲就会变成「抄一段能跑的代码」。
  • 第 2 讲的坎要用「打印」过，不要用「背」过：变换顺序这件事背了必错。把 translate→rotate 与 rotate→translate 两种写法的端点坐标并排打出来，看一眼就懂了，而且一辈子不忘。
  • 第 6 讲的坎要用「计数」过：在 paintEvent 里放一个 static 计数器，然后循环调 update() 一万次，看打印出来的 paint 次数——这个实验比任何文档都能说明「事件循环会合并重绘请求」。
  • API 有疑问就查头文件，别查记忆：本模块每个示例顶部都有一份「本机头文件签名清单」（带行号）。QImage 没有 useCount()、QWidget 没有 setUpdateInterval()、Qt::ClipOperation 没有 UnionClip、路径布尔不叫 unitedPath()——这些坑都是查头文件 + 编译期核对抓出来的，不是背出来的。
  • Qt5 → Qt6 的差异记三条就行：QFontMetrics::width() 没了（用 horizontalAdvance()）；QPainter::RenderHint 里没有 HighQualityAntialiasing；Qt6 没有 QtGui/qgradient.h 这份实现头（渐变声明在 qbrush.h）。三处都在第 1/3/4 讲里实测过。
  • 诚实对待「编没编过」：这一条本模块自己走过回头路。早期写的是「第 5~8 讲只过了 g++ -fsyntax-only -Wall -Wextra，本机链接不了，谁也没运行过这些程序」——那句现在已经不成立了：八讲全部在本机（Qt 6.12.0 + MinGW 13.1.0）编译、链接、-platform offscreen 跑过，ctest -R "^painting_" → 8/8 绿，build/bin 下实际落了 27 张 PNG，输出存档 runlogs/painting_0N_*.log。留这条更正不是为了表功，是为了让你看见环境事实的保质期：一句「本机编不动」躺在那里，等环境好了，它盖住的那一半结论就全成了空话。
  • 「跑过」不等于「验过」：跑通只证明没崩。这一模块里真正的证据是两类数字——生成的 PNG（画面）和打印出来的像素计数/采样值（数）。两者都要看，而且要以数为准：画面会骗人，非透明像素数不会。换机器重跑时重点比对这两样。
  • 本机有一行无害的字体警告：QFontDatabase: Cannot find font directory D:/Qt/6.12.0/mingw_64/lib/fonts。Qt 6 不再自带字体，第 4 讲的文字度量照样能出数（走系统字体），但换一台没装字体的机器，度量数字会变——第 4 讲里那些具体像素宽度是「本机这一轮」的环境事实，别当常数抄。

👴 老师傅的话

徒弟，绘图这块是 Qt 里最「看得见摸得着」的部分，也是最容易把错处藏起来的部分——差半个线宽、错一次变换顺序、少算一个基线，画面只是「有点不对」，不会崩，于是很多人就这么将就下去了。师傅不让你将就。

给你五条压箱底的经验：

  • 第一条：先分清「画布」和「笔」。 前四讲讲的是笔（QPainter + 变换 + 笔刷 + 文字），第 5 讲讲的是布（QImage / QPixmap）。搞混这对概念的人，写出来的程序要么在子线程里造 QPixmap 崩掉，要么在 paintEvent 里反复 QPixmap::fromImage() 把帧率画没。
  • 第二条：绘制代码要能离屏跑。 本模块每个示例都有一条「画进 QImage」的证据链，这不是为了截图好看——能离屏跑的绘制代码，才能被自动化测试、才能被复用、才能在 paintEvent 之外被验证。养成把绘制主体写成 void paintX(QPainter&, const QRectF&, ...) 自由函数的习惯（第 6 讲就这么干的）。
  • 第三条：重绘是「请求」，不是「命令」。 update() 往事件队列里塞一张纸条，事件循环会把同一轮里的一万张纸条合成一次重绘；repaint() 是你冲过去把画布抢过来硬画，会递归、会卡、会绕过合并。默认永远用 update()，范围已知就用 update(QRect)。这条不通，你的控件在拖动时就会抖成一团。
  • 第四条：别在 paintEvent 里改状态。 绘画函数应当是纯函数：读状态、画出去、不写回。在里面自增动画帧号再 update()，就是自己给自己造一个停不下来的重绘循环——第 6 讲专门用一组对照数据把这事演示了一遍。
  • 第五条：知道什么时候该换框架。 一个自绘控件画几十到几百个图形，爽；要画几千个、还要缩放平移命中选择撤销，继续自绘就是跟自己过不去。第 8 讲不是「进阶炫技」，是给「第 6 讲那条路走到哪里该拐弯」画的 realpath 路标。

把这 8 讲啃下来，你就能从「用 Qt 提供的控件」变成「给别人提供控件」——这是入门和资深的一道分水岭。慢慢画，图画不会骗人。加油，徒弟！
