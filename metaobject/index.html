🧬 元对象系统 · Meta-Object

Qt 区别于普通 C++ 的那一层 · 8 讲，从「会用信号槽」到「读懂元对象表」

📖 模块简介

本模块讲 Qt 的元对象系统（Meta-Object System）——信号与槽（signal/slot）、 Q_OBJECT 与 moc、属性系统（Q_PROPERTY）、 QObject 父子树与所有权、运行时反射（QMetaObject）。 前 4 讲教你把信号槽用对；第 5 讲把引擎盖掀开，看 moc 到底生成了什么； 后 3 讲讲长在这张表上的能力：属性、对象树、反射。 学完这 8 讲，你对「为什么 connect 连不上」「为什么槽跑了两遍」「为什么改了属性界面不刷新」 这类问题，就不再是猜了。

环境事实：本资料库基于 Qt 6.12.0，Windows 平台，MinGW-w64（MSYS2 ucrt64，gcc 15.2/16.2）， 构建用 CMake ≥ 3.21 + Ninja，语言标准 C++17（这是 Qt6 的最低要求）。 每一章都是完整可编译的示例 + 详细注释，且都设计成无人值守能自动跑完 （QTimer::singleShot 排脚本 + qInfo() 吐结论 + quit()）。

📚 学习建议

  • 按三段推进：第 1~4 步先把「用」练熟，别急着看表；第 5 步回头把前四步的道理一次性解释清楚；第 6~8 步再往外长。跳过第 5 步直接学属性，你会一直处在「它反正能用」的黑盒状态。
  • 每个示例都要跑：8 个示例都是无人值守的——QTimer::singleShot 排好脚本、qInfo() 打结论、最后自动 quit()。先跑一遍看输出，再回过头读注释，效率比倒过来高得多。
  • 亲手跑一次 moc：第 5 步的注释里有完整命令（moc.exe 05_moc_anatomy.cpp -o out.txt）。一个 30 行的类能生成两百多行表 + switch，看三次就终身不忘，比读十篇博客管用。
  • 第 4 步的规矩要变成肌肉记忆：写带 lambda 的 connect 时永远传 context object。这条规矩的价值要到你踩第二次「界面偶发崩溃」时才显出来，但别等到那时。
  • 第 6~8 步的错误都在运行期：属性名拼错、枚举没写 Q_ENUM、indexOfMethod 返回 -1 还拿去用——编译器一个字都不说。所以这三讲的每个示例都刻意把「失败长什么样」打出来给你看。
  • 记住「未在本机实测编译」：本机运行时不全，示例暂无可执行产物；但 API 全部对着真实头文件核对过，注释里连行号都给了。换到能编译的环境，按每讲顶部注释块里的 CMake 目标名构建即可。

👴 老师傅的话

徒弟，元对象系统这块，外面教程多、错误更多。师傅不给你背 API，先给你三条心法：

  • 第一条：信号就是一个成员函数，别把它当魔法。 它是 moc 替你写好实现体的 public 函数，函数内容就是「查这张连接表，把表里的槽挨个调用一遍」。想通了这一句，「没连接时发射为什么不报错」「重复 connect 为什么跑两遍」「同线程为什么是同步调用」全部自动通了。
  • 第二条：Q_OBJECT 不是风格，是入场券。 没写它，你的类就没有自己的元对象表，信号连不上、属性找不到、qobject_cast 返回空、findChild 直接编译不过。而它只声明不实现，所以 .cpp 里的类必须在末尾 #include "本文件名.moc"——这条链接期报错我期望你这辈子只查一次。
  • 第三条：按名字干活，就要接受错误在运行期。 字符串版 connect、setProperty("levle",…)、invokeMethod("sweep") 都把编译器的检查换成了运行时的查表。属性系统、反射这些能力很有价值，但内部热路径一律用函数指针写法，只有插件、配置、QML 这些「名字来自你编译单元之外」的场景才允许按名字。
  • 第四条：寿命问题只有一个解法。 第 3、4、7 讲其实都在讲同一件事——谁先死、谁还持有谁的指针。带 context 的 connect、QPointer、deleteLater()、父子树，全是这一句话的四种写法。别背 API，背这句话。
