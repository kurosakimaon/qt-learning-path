🧵 第柒阶段 · 并发与线程

「只有 run() 跑在新线程里」 · 8 章从亲和性讲到跨进程，全程不调 terminate()

📖 模块简介

到这一阶段，你写的界面已经能动、能画、能编辑了。但只要有一件活超过 100 毫秒——读个大文件、解一次压、连一次网—— 界面就会「未响应」，因为所有槽、所有事件处理器，都跑在同一个线程里。这个线程既要分拣事件，又要干活， 它只能一次干一件。并发这一阶段，就是学「怎么把活分出去，又不把自己弄死」。

Qt 的多线程有一句必须刻进脑子的话：只有 run() 跑在新线程里，别的都在原线程。 QThread 对象本身住在创建它的线程，它的槽、它的信号、它的定时器，全都在那条线程上执行——它只是 「一个新线程的遥控器」。第 1 讲先把这句话用可打印的三个线程身份钉死，第 2 讲把「每个 QObject 归哪条线程」 这条第一原理讲透，第 3 讲才让这两条线交汇成跨线程信号槽的完整规则。

本模块共 8 章：第 1 讲两条写法对照（继承 run() vs worker-object + moveToThread）； 第 2 讲线程亲和性；第 3 讲连接类型与参数跨线程搬运；第 4 讲锁、原子、等待条件、信号量各自的失效形状； 第 5 讲 QtConcurrent（不想自己管线程时）；第 6 讲 QRunnable + QThreadPool（线程池是 QtConcurrent 的底座）； 第 7 讲协作式取消与收尾；第 8 讲本地进程间通信（QLocalServer / QLocalSocket，Windows 上是命名管道）。 每一讲都是完整示例，自己置标志、自己取证据、自己吐结论，跑完就退出，不留后台线程。

环境事实：本资料库基于 Qt 6.12.0，Windows 平台，MinGW-w64（MSYS2 ucrt64，gcc 15.2/16.2）， 构建用 CMake ≥ 3.21 + Ninja，语言标准 C++17。8 个目标（threads_01_thread_basics … threads_08_local_ipc）已在顶层 CMakeLists.txt 的「第柒阶段 · 并发与线程（threads/）」一节登记； 第 5、8 讲分别多链了 Qt6::Concurrent 与 Qt6::Network。

第 1 步 · 第一道坎
🚦
01 · QThread 的两条路
继承 QThread 重写 run()，和 worker-object + moveToThread，两条都跑一遍并打印三个线程身份。核心证据：同一个 QTimer 在 run() 里不 exec() 时零 tick，exec() 后开始走；currentThread() == this 只在 run() 里成立。另讲 QThread::create()（静态模板、返回堆上的 QThread*、标了 [[nodiscard]]）与 idealThreadCount()，以及为什么 terminate() 一次都不调用。
范式转变进阶入门
第 2 步 · 第二道坎
🧭
02 · 线程亲和性
每个 QObject 心里揣着一条线程（qobject.h 第 143 行 thread()，第 147 行 moveToThread 返回 bool——成败当场告诉你）。谁创建就归谁；有 parent 挪不动；QTimer 必须由它所属线程 start()（正例在 worker 的槽里 new，反例在主线程 start）；loopLevel() 当场验证有没有事件循环；跨线程 delete 的代价与 deleteLater 的正解。
亲和性框架机制
第 3 步 · 第三道坎
📡
03 · 跨线程信号
Auto 不是「自动挑更好的」，它只是一条规则：发射那一刻比 currentThread() 与接收者 thread()，相等按 Direct、否则按 Queued。Direct 在子线程栈上跑槽；Queued 立刻返回、槽等接收者循环；参数按值拷进事件，所以自定义类型要过元类型登记这一关（QMetaType::fromType 能编译 ≠ isRegistered() 为真）。附「队列里压着几个事件」的原子计数证据。
线程判定框架机制
第 4 步
🔒
04 · 同步：锁、原子、等待条件、信号量
四件工具按「线程封闭 > 消息传递 > 原子 > 锁」的优先顺序讲。裸 ++ 的丢更新先用手工交错演一遍（必然错），再真并发跑（概率）；两个原子操作拼不成一个复合原子操作；QMutexLocker 的四种写错形状里两种编不过、两种静默；QWaitCondition 必须配锁用、醒来必须重查条件（虚假唤醒）；QSemaphore 的生产者消费者账本。
并发正确性进阶入门
第 5 步
⚡
05 · QtConcurrent
「活交出去、结果拿回来、线程我不管」。run 的四条签名与 Q_NODISCARD（不要结果就别用 run，去第 6 讲）；参数被拷贝进 tuple；QFutureWatcher 每个回调打印所在线程（watcher 活在哪条线程，信号就在哪发）；result() 会阻塞而 isFinished() 不会；mapped / mappedReduced / filtered 是命名空间自由函数、不是 QFuture 成员；filter 原地改容器这一坑。
进阶入门框架机制
第 6 步
🧰
06 · QRunnable 与 QThreadPool
QRunnable 不是 QObject：没有元对象、没有亲和性、不能 emit，想把结果送回去必须另攥一个 QObject（三个 static_assert 钉死）。autoDelete 默认 true 决定谁 delete（析构计数器为证）；start 的裸 int 优先级与 QThread::Priority 不是一回事；tryStart 不排队；maxThreadCount 压到 1 把队列排出来核对顺序；waitForDone 的期限。
线程池框架机制
第 7 步
🛑
07 · 取消与收尾
「停」只有一种正确形状：任务自己在检查点看标志再 return。三种局面对应三套 API：requestInterruption / isInterruptionRequested 管线程（池里的线程拿不到）；QFuture::cancel() 对「排队中 / 正在跑 / 已跑完」做三件不同的事；QtConcurrent 在空池上会同步在调用者线程走完。前提不成立的实验记 stalled，不硬拗成绿；收尾一律 quit + wait(期限)，绝不 terminate。

08 · 本地进程间通信
QLocalServer/QLocalSocket（Windows 命名管道、Linux macOS 本地 socket）。同名第二个服务端被拒——这就是「单实例」的地基。管道里没有「消息」只有字节：五条消息拆三段发，用长度前缀找回来，并打印「第一块只有 7 字节」的半包现场；帧头不可信（声称 1 GiB 必须拒且已解析的不回滚）；每连接一份解析器与生命周期。

📚 学习建议

  • 先跑第 1 讲，把三个线程 id 抄在纸上：主线程、run() 里的线程、QThread 对象所在线程。这三个 id 的关系，是你后面所有判断的地基。
  • 每写一个 moveToThread，先问两件事：对象有没有 parent？它是不是在「当前线程」被创建、然后要挪去别处？前者让挪动失败，后者要保证挪动发生在它开始干活之前。
  • 跨线程只传值：信号参数按值拷贝，所以传引用/指针等于把别人的内存地址递出去。真要共享，先回到第 4 讲那四个字的顺序：封闭 → 消息 → 原子 → 锁。
  • 把「跑通」和「写对」分开：第 4 讲故意先用手工交错把错演出来，就是因为并发 bug 只靠「跑一次没崩」发现不了。你改代码时也要保留这套取证习惯。
  • 所有等待都带期限：wait(3000)、QSignalSpy::wait(2000)、waitForDone(5000)。没有期限的等待，在别人的机器上就是一次挂死。
  • 记住「未链接未运行」：本机此刻编不动 Qt 运行时；换到能链接的环境按注释里的目标名构建（-platform offscreen 可无头跑），再和你抄下的线程 id 对一遍。

👴 老师傅的话

徒弟，线程这一块，师傅见过太多人「会用」却「用错」。它跟别的地方不一样：别的地方写错了当场报错，这里写错了十次都对，第十一次在客户现场崩。所以这一阶段我不教你写得多花，只教你两件事——知道东西在哪条线程上，以及把结论变成能核对的数。

几条压箱底的忠告：

  • 第一条：QThread 不是线程，是遥控器。 只有 run() 在新线程里跑；QThread 对象自己的槽还在老线程。你把它当「线程对象」用，就会写出「我在子线程里 new 的定时器怎么不响」。
  • 第二条：归属只认创建者。 想让一个 QObject 在 worker 线程里活，就得让它在 worker 线程里被创建（或者在它开始干活前 moveToThread 过去），而且它不能有 parent。这一条解释了 Qt 里九成的「偶发崩溃」。
  • 第三条：能用消息就不用锁。 线程封闭（每个线程自己的数据）最好；跨线程信号次之；原子只解决单个变量的单步操作；锁是最后的工具，也是最贵的工具。顺序反了，你就是在用最贵的方式换最少的确定性。
  • 第四条：terminate() 永远不是选项。 它杀掉整条线程：锁还攥着、半截数据结构还写着、栈还没返回。协作式取消 + quit + 带期限的 wait，才是「停下来了，而且还能继续用」。
  • 第五条：凡是「时序」结论，只能来自被数出来的东西。 线程调度不欠你任何承诺。所以示例里凡是概率性的结果我都标了概率，凡是关系性的结论我都写成关系（Queued 返回时槽还没跑、Direct 在同一条栈上）。你也照这个标准要求自己。
