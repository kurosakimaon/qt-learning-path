🧩 第陆阶段 · 模型/视图与委托

把「数据」和「画出来的那一格」彻底分开 · 8 章循序渐进，从五角色总览到 10 万行不卡

📖 模块简介

这里是全课程真正换脑子的地方。前几阶段是「一个控件一份状态」，从本阶段开始， Qt 的列表/表格/树走的是 Model / View / Delegate / Selection / Proxy 五角色分工： 数据只住在模型里，视图每画一格都现场来问 data(index, role)； 委托决定这一格怎么画、编辑器怎么造、怎么把编辑结果写回模型； 选中了哪些不归视图管，它是一份住在 QItemSelectionModel 里的模型侧状态； 要排序过滤，就在源模型前面再套一层代理模型的坐标系。

本模块共 8 章：第 1 讲摆清五角色与「拉取式（pull-based）」这条主线；第 2、3 讲手写模型， 把「答话」和「接活」两半都自己实现一遍；第 4 讲把委托这一层的接口与生命周期讲透；第 5 讲上代理模型 （两套坐标系，本模块最容易翻车的一层）；第 6 讲讲选择模型；第 7 讲评价便利类 QStandardItemModel 的账；第 8 讲收在视图侧的调优——为什么 10 万行不卡、又是怎么被人一句话弄卡的。 每一讲都是完整可编译的示例 + 详细注释，全部设计成无人值守跑完、自己吐证据： 用 QTimer::singleShot 排动作、用 data() 计数器与 QElapsedTimer 拿数据、 用 qInfo() 打印结论，最后 QCoreApplication::quit()。

环境事实：本资料库基于 Qt 6.12.0，Windows 平台，MinGW-w64 GCC 13.1.0（Qt 官方安装器自带：D:\Qt\Tools\mingw1310_64）， 构建用 CMake ≥ 3.21（本机 3.30.5）+ 生成器 MinGW Makefiles，语言标准 C++17。构建目标名就写在各文件顶部注释块里 （形如 model_view_05_proxy_model），8 个目标在顶层 CMakeLists.txt 的 「第陆阶段 · 模型/视图与委托（model_view/）」一节里已登记。

实测口径：本模块 8 个目标已在本机真实编译、链接、运行（Qt 6.12.0 + MinGW 13.1.0， Windows，QT_QPA_PLATFORM=offscreen），全部包含在顶层 ctest 的 73/73 里； 每个 .cpp 也过 moc + g++ -std=c++17 -Wall -Wextra（零 error、零 warning）， 文中每一个类、函数、重载、枚举值都对着本机真实头文件逐字核对过 （D:\Qt\6.12.0\mingw_64\include），查不到签名的一律不写。 各目标自己那行「硬账 / 合账」结论写在了源码头部，原始输出存档在 runlogs/<目标名>.log（UTF-8；重跑：bash _tools/run_all.sh '^model_view'）。 换 Qt 版本 / 换平台 / 换窗口大小之后，带具体数字的预期请以下面这些打印为准。

8 张卡片 = 8 章，按 第 1 步 → 第 8 步 一张张往下学，别跳。 这条主线是「先换脑子、再造模型、再打通编辑回路、再讲画与选、最后算性能账」： 第 1 步认清五角色与拉取式 → 第 2 步手写模型把「答话」写对 → 第 3 步把「接活 + 发信号」这条回路补上 → 第 4 步委托管画与编辑 → 第 5 步代理模型（坐标系换了）→ 第 6 步选择模型（选择不在视图里）→ 第 7 步便利类的账 → 第 8 步视图侧调优收尾。 本模块有四道硬坎，每一道都会真的咬人： ① 第 1 步「观念转变」坎——数据不在控件里、QModelIndex 只是带内部指针的坐标， 这一步没转过来，后面全是背 API； ② 第 2 步「手写模型」坎——五个纯虚函数的签名（const、参数表）差一个字就编不过， createIndex / internalPointer 的生命周期差一点就是悬垂指针； ③ 第 4 步「委托」坎——setEditorData 与 setModelData 方向相反， 画一格与造编辑器的时机又不一样，搞混就会写出「一编辑就丢值」的代码； ④ 第 5 步「索引映射」坎——套了代理之后视图手里的 index 属于代理， 拿它直接问源模型不报错、只给空值，这是「偶现空表格 / 删错行」这类线上事故的经典病根。 模型/视图是全模块里最容易被跳过的一段：界面照样能摆出来，就以为懂了； 可它恰恰是最容易被面试追问、也最容易被线上事故追回来的一段 （「为什么你一千行就卡」「删完行选中怎么错位了」「过滤后为什么取到空」）。别跳。 每章重点与练习见 📖 学习指南。

第 1 步 · 观念坎
🧭
01 · 五角色总览
Model / View / Delegate / Selection / Proxy 一次性摆清；用「视图子对象数量与行数无关」证明格子不是控件；QModelIndex 只是带内部指针的坐标（不持数据、会失效、不能跨模型混用）；data(index, role) 是拉取式；最后用 QStandardItemModel + QTableView 跑通最小闭环。
范式转变进阶入门
第 2 步 · 第二道坎
🛠️
02 · 手写 QAbstractTableModel
把便利类扔掉：index / parent / rowCount / columnCount / data 逐个逐字核对签名；加 headerData 与 roleNames；角色枚举真名真值（Qt::DisplayRole=0 … Qt::UserRole=0x0100，Qt6 已无 Qt::SortRole）；createIndex 与 internalPointer 存什么、std::vector 扩容为何让旧 index 悬垂；挂 5000 行 × 4 列用计数器证明视图只问可见那几格。
手写模型进阶入门
第 3 步
✏️
03 · 可编辑模型：flags / setData / dataChanged
把「接」这一半补上，并画清回路：setModelData → setData → emit dataChanged → 视图标脏 → 重绘再问 data()。两个模型实例 + 两个视图做对照，漏发信号那个的 dataChanged 槽计数为 0，强制重绘才「露馅」——这就是「一改就错、一滚就对」的病根；另讲 flags() 各值真名、setData 的校验顺序、beginInsertRows/endInsertRows 与 reset 的取舍。
进阶入门
第 4 步 · 第三道坎
🎨
04 · 自定义委托（Delegate）
视图与模型之间那个「画一格 + 管编辑器」的角色：paint(QPainter*, QStyleOptionViewItem, QModelIndex) 怎么画、sizeHint 怎么定尺寸、createEditor / setEditorData / setModelData / updateEditorGeometry 这条编辑链的方向与时机（入数据与回数据是两回事），以及 editorEvent / helpEvent / destroyEditor。接口按本机 qabstractitemdelegate.h 的公开虚函数核对。
委托进阶入门
第 5 步 · 第四道坎
🪞
05 · QSortFilterProxyModel
在源模型前再套一层坐标系：源模型 1 万行 × 4 列，代理只露过滤后的行；mapToSource / mapFromSource 与 mapSelectionToSource 做成硬证据（拿代理 index 直接问源，拿到的是空 QVariant）；静态匹配 setFilterFixedString + filterKeyColumn，与重写 filterAcceptsRow / filterAcceptsColumn / lessThan 两条路的分工；外部判据变了要 invalidate() 或 begin/endFilterChange()（老的 invalidateFilter 在本机已 protected 且标废弃）；dynamicSortFilter 与视图 setSortingEnabled 的关系。
两套坐标系框架机制
第 6 步
🖱️
06 · QItemSelectionModel
「选中了哪些」是模型侧的一份数据，视图只是读写面板：三个视图共用一个选择模型会同时高亮；QItemSelection 是矩形范围列表（不是逐格索引），范围两角本身就是 QPersistentModelIndex；逐条打印 SelectionFlags 真值（Qt 6.12 里没有 CommandMask），并说清 selectionChanged 不带命令、flags 是视图侧 selectionCommand() 翻译出来的；裸 QModelIndex 与持久索引在插一行后的两种下场。
框架机制进阶入门
第 7 步
📦
07 · QStandardItemModel / QStandardItem
便利类的账怎么算：卖点是不写五个虚函数、也不用自己 emit dataChanged（内部 _q_emitItemChanged 代劳，用信号计数证明）；代价是每格一个独立堆对象 + d-pointer（Qt6 里 QStandardItem 已不继承 QObject，流行说法要纠正）；树和表共用同一套 item；takeRow / takeItem 的所有权陷阱；findItems ≠ 过滤；10 万行 × 4 列两份模型并排计时，最后给「三档判断」什么时候必须自己写。
进阶入门
第 8 步 · 性能账
⚡
08 · 视图侧调优与行为
10 万行为什么不卡、又是怎么被弄卡的：拉取式只问可见区（打印被问到的行区间）；隐藏的两笔开销是表头 headerData 与每格 sizeHint；resizeColumnsToContents() 会遍历所有行（用计数器数出来），写成 ResizeToContents 动态模式后每次 dataChanged 都重来；verticalHeader()->hide()、ScrollMode（枚举属于 QAbstractItemView）、QTreeView::setUniformRowHeights、EditTrigger、wordWrap / iconSize / updateThreshold、setModel 后 view->reset() 清了什么，末尾给「默认 vs 调优」总账。

📚 学习建议

  • 按顺序学，尤其别跳第 5、6 步：很多人「界面能摆出来」就以为模型视图懂了，代理与选择这两层一碰到真实需求（过滤后取数据、批量选中删行）就露底。
  • 先读指南和顶部注释块：每一讲动手前先读本页 📖 学习指南 和该 .cpp 顶部「本讲解决什么问题」，把「这一讲要钉死哪几条事实」弄清楚再敲。
  • 签名逐字抄头文件，别凭记忆：第 2 步的五个虚函数、第 5 步的 filterAcceptsRow/filterAcceptsColumn/lessThan，都要带 const 并写 override；写错不是「不工作」，是「变成另一个函数」。
  • 跑之前先想清楚要拿什么证据：本模块每讲都是「计数器 + 计时 + 打印区间」的取证式示例。你改代码时也要留这套习惯——性能问题、坐标系问题的结论只能来自被数出来的东西。
  • 把四道坎各撞一遍：第 1 步的观念（格子不是控件）、第 2 步的 internalPointer 悬垂、第 4 步的 setEditorData/setModelData 方向、第 5 步的「拿代理 index 问源」，每道坎都亲手改错一次再改回来。
  • 先跑再看结论：这 8 个目标本机都已编译、链接、无头跑过（ctest -R model_view，或 bash _tools/run_all.sh '^model_view'），输出存档在 runlogs/。示例里那些「几行被调用、几个信号 fired」的计数都是打印出来的，不是你肉眼数出来的——你自己改过之后，重跑一遍再下判断。

👴 老师傅的话

徒弟，这一阶段是 Qt 里「第一道真正的工程分水岭」。前面学控件，拼的是「会不会摆」；到这里拼的是想没想清楚数据住在哪儿。模型/视图这套不是 Qt 发明的花样，它是 MVC 在 GUI 里最落地的一次实现——你把它想通，以后看任何表格控件、列表控件、甚至别人家的前端框架，都是同一副骨架。

师傅给你几条压箱底的忠告：

  • 第一条：先把「拉取式」刻进脑子。 视图不问「你变了吗」，它问「现在是什么」。你在 data() 里省下的每一分力气，都会翻倍还到滚动条上；你在 data() 里藏的每一分重活，都会变成「一滚就顿」。第 1、2、8 步三次给你数出来，不是吓你。
  • 第二条：改完数据必须发信号，顺序不能反。 beginInsertRows → 改容器 → endInsertRows；改完格子 → emit dataChanged。反了或者忘了，症状是「一改就错、一滚就对」这种最耗人的玄学 bug。第 3 步那个对照实验，你要能自己复述出结论。
  • 第三条：索引是坐标，不是身份证。 QModelIndex 会失效、不能跨模型混用；要跨结构性变更留住一个格子，用 QPersistentModelIndex，但要知道它是登记在册的开销。套了代理之后，视图给的 index 一律先 mapToSource 再问源模型——这一条值一次线上事故。
  • 第四条：便利类要用得明白，不是用得省事。 QStandardItemModel 三十行出一屏，是好事；拿它撑十万行数据，就是自己给自己埋雷。判断标准只有三个问题：数据本来是谁的、规模多大、要不要自己控角色与信号。
  • 第五条：不确定的 API 一律查头文件。 本模块里师傅把好几条「网上人人都在背」的说法当场拆了（filterFixedColumn 根本不存在、Qt6.12 的 SelectionFlag 里没有 CommandMask、ScrollMode 不属于 QAbstractScrollArea、Qt6 的 QStandardItem 不再是 QObject）。写 Qt 和做人一样：编不出来的名字就别写进去。

慢慢啃，这一块值得你多花两个周末。把这 8 讲拿下，你写的就不再是「能看的界面」，而是撑得住数据、也撑得住面试和线上的界面。加油，徒弟！
